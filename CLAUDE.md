# CLAUDE.md

Plezy is a Flutter client for Plex and Jellyfin (upstream: `edde746/plezy`). This checkout is the
**native LG webOS port** (branch `webos-native-working`), built with LG's `flutter-webos` SDK, with
hardware video through LG's `NDL_media` and a custom subtitle engine.

## Remotes and branches

| Remote | Repository | Notes |
| --- | --- | --- |
| `origin` | `GLNick/plezy-webos` | The port author's repository (read-only for us) |
| `fork` | `alcroito/plezy` | Our fork of `edde746/plezy`; CI and releases run here |

- Work on `webos-native-working`. Pushes to it on `fork` trigger `.github/workflows/webos.yml`.
- Push over SSH (`git@github.com:alcroito/plezy.git`) when `.github/workflows/` changes: the `gh`
  OAuth token lacks the `workflow` scope.
- Tags `v*-webos*` on `fork` publish a release with both IPKs and Homebrew Channel files.

## Key facts

- **LG supports only webOS 26 Re:New.** One NDK (11.2.0, x86_64 Linux only), `webos26` engine
  artifacts only, no engine or embedder source.
- **Two packages, both 32-bit ARM**, same app id `com.edde746.plezy`:
  - `_arm_webos25-26.ipk`: unpatched LG output; needs glibc 2.38, so in practice webOS 26 only.
  - `_arm_webos6-24.ipk`: patched by `scripts/webos/build_32bit_ipk.sh` (compat shim
    `libwebos_compat32.so`, ELF patching, ustar repack); runs on webOS 24 (glibc 2.35), likely 25,
    not on webOS 23 or older despite the name.
- **`Platform.isLinux` means webOS in this port.** `lib/mpv/player/player.dart` returns
  `PlayerWebos` on Linux, `PlatformDetector` treats Linux as a TV, and `lib/main.dart` installs webOS
  key/back hooks when `Platform.isLinux`. The desktop Linux build is not a target on this branch.
- Toolchain: `flutter-webos` `950398131830e9bd5dc91e588c3db8f5c42322be` (Flutter 3.38.10, Dart
  3.10.9), NDK 11.2.0, Node.js 22 with `@webos-tools/cli` 3.2.6. Upstream Plezy targets newer
  Flutter; dependencies in `vendor/` were patched for Dart 3.10 (`scripts/webos/vendor_diffs.patch`).
- `pubspec.lock` must be resolved with Flutter 3.38.10 (`flutter-webos pub get`).

## Where the webOS code lives

| Path | Purpose |
| --- | --- |
| `webos/` | Runner (`runner/main.cc`: scale 1.5x, view properties), `meta/appinfo.json`, `flutter-conf.json` |
| `webos/runner/webos_pointer_seats.cc` | Works around LG's embedder listening for the pointer on one seat only (Magic Remote fix) |
| `webos/flutter/ephemeral/` | Generated by `flutter-webos`; contains LG's `runner_base` (do not edit) |
| `webos_plugins/` | LG's webOS plugins, vendored; `video_player` carries the port's NDL/Wayland patches |
| `vendor/` | Upstream Dart dependencies adjusted for Dart 3.10 |
| `lib/mpv/player/platform/player_webos.dart` | Video player on top of `video_player_webos` (NDL) |
| `lib/mpv/player/platform/webos_subtitle_engine.dart` | ASS/SSA, SRT/VTT, PGS rendering and MKV subtitle demuxing |
| `lib/main.dart` | webOS key, back-policy and pointer hooks (`_installWebosBackAndNavigationHooks`) |
| `lib/utils/app_logger.dart` | Also appends every log line to the app's `appdata/plezy_runtime.log` on the TV |
| `scripts/webos/` | `env.sh`, `build_32bit_ipk.sh`, `ci/` (setup, build, Homebrew repo, publish) |

## Building

On x86_64 Ubuntu (locally the OrbStack VM `ubuntu`, which mounts this checkout at the same path):

```bash
scripts/webos/ci/setup-toolchain.sh   # once; installs NDK, flutter-webos, Node, ares
scripts/webos/ci/build.sh             # both IPKs into dist/
```

In the OrbStack VM, prefix `PATH=$HOME/bin:$PATH` (working `tar`, see `WEBOS_DEVICE_NOTES.md`). The
build cannot run on macOS directly.

Upstream checks from `CONTRIBUTING.md` (`dart format`, `flutter analyze`, `scripts/run_tests.sh`,
`scripts/codegen.sh`) are written for upstream's Flutter. On this branch the code generators
(`build_runner`, `freezed`, `json_serializable`, `drift_dev`, `slang_build_runner`) are commented out
in `pubspec.yaml`, so `scripts/codegen.sh` does not run; generated files are committed.

## Testing on the TV

Install and launch through Glasshouse's HTTP API on the TV, read logs over root SSH; full commands
in `WEBOS_DEVICE_NOTES.md`. `luna-send` over SSH does not launch apps on the test TV.

## Rules for changes

- Keep upstream compatibility in mind: webOS-specific behavior is gated on `Platform.isLinux` or
  `PlatformDetector.isTV()`; avoid changing shared code paths without that gate.
- The runner exports `wl_proxy_add_listener` (`webos/runner/user_build.cmake`); keep the export
  flag, or the Magic Remote fix silently stops working.
- Do not edit `webos/flutter/ephemeral/`; override behavior in `webos/runner/main.cc`
  (`OnBuildViewProperties`) instead.
- Diagnostic code marked `TEMP` is not committed.
- When `build_32bit_ipk.sh` or the engine version changes, re-check the patched package's glibc and
  libstdc++ requirements (`readelf -V`, see `WEBOS_COMPAT_PATCHING.md` section 8).
- Release notes and docs state what was verified on a TV versus derived from static analysis.

## Open issues

- Magic Remote pointer: LG's embedder handles pointer input on one Wayland seat only; the runner
  works around it (`WEBOS_DEVICE_NOTES.md` section 8). Not tested on webOS 25-26.
- The patched package stores app data (including the Plex token) in a world-writable folder; see
  `WEBOS_COMPAT_PATCHING.md` section 7.
